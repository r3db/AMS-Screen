It gives you a dedicated Bambu Lab AMS Screen via a Raspberry PI.

**Note: This is a very early prototype.**
**In order for it to work this device and you bambu printer need to be in the same network**

<img width="1262" height="701" alt="image" src="https://github.com/user-attachments/assets/879375ba-5043-4e12-a361-89d65500b8b0" />

**To compile:**
```
dotnet publish -c Release -r linux-arm --self-contained true
```

**To Run:**

Copy the files generated by the compiler, most likely here:
```
src\AMS-Screen\bin\Release\net10.0\linux-arm\publish\
```
and move them to a folder in your raspberry pi, in my case I created a folder in my desktop called: **ams-screen**.

Give it execution persission
```
chmod +x Desktop/ams-screen/AMS-Screen
```

Now we need to make sure it loads everytime it restarts.

```
sudo nano /etc/systemd/system/ams-screen.service
```

Paste this:

```
[Unit]
Description=AMS Screen .NET Web Application
After=network.target

[Service]
Type=simple
User=r3db
WorkingDirectory=/home/r3db/Desktop/ams-screen
ExecStart=/home/r3db/Desktop/ams-screen/AMS-Screen --urls "http://0.0.0.0:5000"
Restart=always
RestartSec=5
Environment=ASPNETCORE_ENVIRONMENT=Production
Environment=DISPLAY=:0
Environment=XAUTHORITY=/home/r3db/.Xauthority

[Install]
WantedBy=multi-user.target
```

Make sure you update **WorkingDirectory** and **ExecStart** to the folder you used.

Run these, restart and you should be good to go.
```
sudo systemctl daemon-reload
sudo systemctl enable ams-screen.service
sudo systemctl start ams-screen.service
```

One final bit of configuration, in your publish folder you'll find **appsettings.json** you need to update it with your printer settings.

```
{
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  },
  "BambuPrinter": {
    "IpAddress": "Your-Printer-Ip-Address",
    "LanCode": "Your-Lan-Code-Check-Your-Printer",
    "Serial": "Your-Serial-Check-Your-Printer"
  },
  "AllowedHosts": "*"
}
```
